## 1. Git: двуязычное ведение

### Подготовка рабочей копии

Локальная папка `PSI-lab2-ui-tickets` была ZIP-архивом без `.git` и со старым README.
Она превращена в настоящий клон ветки без перезаписи рабочих файлов:
`git init` → `git remote add origin` → `git fetch` → `git reset origin/lab2-ui-tickets`
(индекс и HEAD берутся с GitHub, файлы на диске не меняются) → `git checkout` двух README.
Отличия ZIP от ветки предварительно сверены: остальные файлы различались только окончаниями строк.

Локальный `data/students.xlsx` намеренно **не закоммичен**: в нём добавлены три студента группы
IA-2303 с реальными ФИО, публиковать их в открытом репозитории без вашего решения нельзя.
Файл остаётся изменённым только на вашем компьютере. Лишний пробел в «Пятков » приложение
обрезает, это закреплено тестом `test_trailing_spaces_in_cells_are_trimmed`.

### Правила

- `CONTRIBUTING.md` (EN+RU): ветки, формат коммитов, теги, окончания строк.
- `.gitmessage.txt` — шаблон сообщения, подключён командой `git config commit.template .gitmessage.txt`.
- Формат: [Conventional Commits](https://www.conventionalcommits.org/ru/), заголовок
  `type(scope): English summary — русское резюме`, в теле два раздела, `EN:` и `RU:`.
- `.gitattributes`: в репозитории LF, в рабочей копии Windows — CRLF; `.xlsx`/`.docx`/`.png`
  помечены как бинарные. Проверено `git add --renormalize .`: массового диффа нет.
- Перенос файлов (`git mv`) вынесен в отдельный коммит, чтобы `git log --follow` сохранял историю.
- Каждый коммит атомарный, тесты после него зелёные. Ветка отправлена обычным `push`,
  без `--force`. В `main` ничего не сливалось.

## 2. Архитектура по SOLID

### Что было не так

- `gui.App.reload_sources()` сам создавал `ResultsJournal`, вызывал `load_students`/`load_tickets`
  и показывал `messagebox`: интерфейс зависел от Excel, Word и стандартных диалогов
  (нарушение DIP). Протестировать логику экрана без окна было нельзя.
- `ResultsJournal` и хранил строки в Excel, и решал, какой билет «первый» для студента (SRP).
- Случайный выбор билета был зашит в `TicketService` (OCP).
- У ошибок не было общего предка: каждый тип ловился отдельно.

### Что стало

```
domain/          Student, Ticket, JournalRow, Assignment, Roster, first_ticket_of
                 DataSourceError ← StudentsFileError, TicketsFileError, JournalError ← JournalLockedError
application/     ports.py (Protocol), TicketService + RandomTicketPicker, DataLoader,
                 SelectionState, MainPresenter + ViewState, formatting
infrastructure/  XlsxStudentsSource, DocxTicketsSource, XlsxJournal (адаптеры портов)
ui/              theme, widgets, MainWindow (пассивное представление), TicketWindow, TkDialogs, platform
bootstrap.py     корень композиции — единственное место с конкретными классами
```

| Принцип | Реализация | Чем подтверждено |
|---|---|---|
| S | Парсер Word, журнал Excel, правило выдачи (`TicketService`), логика экрана (`MainPresenter`), отрисовка (`MainWindow`), форматирование (`formatting.py`) разделены. Правило «первого билета» — чистая функция домена. | `test_models.py`, `test_formatting.py` проверяют логику без файлов |
| O | Выбор билета — стратегия `TicketPicker`, тема — экземпляр `Palette`. | в тестах вместо случайной стратегии подставляется `FixedPicker`, сервис при этом не меняется |
| L | Все источники бросают наследников `DataSourceError`; `XlsxJournal` и `InMemoryJournal` взаимозаменяемы. | `test_journal_contract.py`: один набор тестов для обеих реализаций |
| I | Узкие порты `JournalReader` / `JournalWriter` / `JournalInitializer`, `TicketIssuer`, `Dialogs`, `MainView`. | истории выдач нужен только reader, загрузчику — только initializer |
| D | Сервис, загрузчик и презентер зависят от `Protocol`; `bootstrap.build_app` собирает Excel + Word + Tk. | e2e-тесты подменяют диалоги через параметр `build_app(dialogs=...)` |

Главное окно сделано **пассивным представлением (MVP)**. Оно получает готовый `ViewState`
(списки, состояние кнопки, статус и его цвет, подсказку, статистику, историю) и передаёт
действия презентеру. Повтор при блокировке журнала, статусы с правильными формами слов
(«3 группы, 5 студентов, 21 билет»), подсказка о повторе — всё это теперь в `MainPresenter`
и проверяется 18 модульными тестами без Tk.

## 3. Интерфейс

### Дизайн-система (`ui/theme.py`)

- Палитры `LIGHT` и `DARK` из 28 цветовых токенов (фон, поверхность, текст, акцент, состояния
  success/warning/danger, градиент шапки). Окна не содержат «магических» цветов.
- **Доступность:** все пары «текст — фон» проходят WCAG 2.1 AA (контраст ≥ 4.5), это проверяет
  `test_palette.py`. При проверке нашлись и исправлены три пары: белый текст на бейджах
  (2.7–3.3), hover кнопки в тёмной теме (4.47), кнопка темы в шапке (4.26).
- Шрифты: Segoe UI / Segoe UI Semibold в Windows, в других ОС — Inter, Ubuntu, DejaVu Sans и т. п.
- Масштаб: включена DPI-осведомлённость Windows (без неё на 125–150 % текст размыт), все отступы
  пересчитываются через `theme.px()`.
- Стили ttk на базе `clam`: основная и вторичная кнопки с кольцом фокуса цвета акцента вместо
  пунктира, комбобоксы (включая выпадающий список), таблица, полоса прокрутки.

### Главное окно

- Градиентная шапка с логотипом, заголовком, версией и кнопкой «☾ Тёмная тема / ☀ Светлая тема».
- Карточка «Получение билета» с номерами шагов 1 и 2, подсказка под выбором студента:
  «Ранее выдан билет № 4 — при повторном обращении выдаётся тот же» или «Билет ещё не выдавался —
  номер будет выбран случайно».
- Плитки статистики: группы, студенты, билеты, выдано.
- Таблица «Последние выдачи» (30 последних записей журнала): чередование строк, повторы
  приглушены, при пустом журнале — «Пока никто не получил билет».
- Строка состояния с цветной точкой (успех / предупреждение / ошибка / инфо) и подсказкой по клавишам.

### Окно билета

- Градиентная полоса: «ЭКЗАМЕНАЦИОННЫЙ БИЛЕТ», крупный «№ 7», ФИО · группа · дата и время,
  бейдж **НОВЫЙ** (зелёный) или **ПОВТОР** (янтарный).
- Вопросы в номерных кружках с тонкими разделителями.
- Жёлтая плашка «Повторное обращение…» или красная «Билета с этим номером больше нет в tickets.docx…».
- Модальное: `Esc`, `Enter` или кнопка «Готово» закрывают только его.

### Удобство

- `Enter` выдаёт билет, `F5`/`Ctrl+R` перечитывают файлы, `Ctrl+T` меняет тему. Сочетания
  продублированы для русской раскладки (`Ctrl+К`, `Ctrl+Е`).
- После выбора группы фокус переходит на список студентов, после выбора студента — на кнопку.
- Параметр `--theme system|light|dark`; `system` читает настройку Windows «Режим приложений».
- Тёмный системный заголовок окна в тёмной теме (Windows 10/11), иконка окна рисуется в коде.

Скриншоты лежат в `docs/screenshots/`, пересоздаются командой `python tools/make_screenshots.py`.

### Сложные места и их решения

1. **Нажатия клавиш без фокуса ОС.** Если во время прогона пользователь работает в другом окне,
   Windows не отдаёт фокус окну тестов, и Tk молча выбрасывает сгенерированные клавиши.
   Именно поэтому старый тест `Esc` иногда падал. Хелпер `tests/gui_support.press()` сначала
   пробует настоящий `event_generate`. Если фокуса нет, он выполняет привязки по `bindtags`
   виджета (виджет → класс → окно → `all`) с подстановкой `%`-полей и учётом `break`, как сам Tk.
   Оба пути проверены: весь набор UI-тестов проходит и в принудительном режиме диспетчеризации.
2. **`Ctrl + буква` в Tk для Windows.** Сгенерированное `<Control-t>` приходит с `keysym='??'`,
   так что привязка не срабатывает (настоящее нажатие работает). Для таких сочетаний `press()`
   всегда использует диспетчеризацию по `bindtags`.
3. **«Файл открыт в Excel».** В Windows e2e-тест открывает `results.xlsx` через `CreateFileW`
   с режимом совместного доступа «только чтение», ровно как Excel. Приложение видит настоящую
   ошибку доступа. В Linux подменяется `os.replace`.
4. **Модальные `messagebox`** нельзя нажать из теста, поэтому диалоги — порт `Dialogs`,
   и тесты передают `FakeDialogs` с заранее заданными ответами.
5. **Ошибки в обработчиках Tk** не роняют тест, а лишь печатаются. В UI- и e2e-тестах
   `report_callback_exception` их собирает, и `tearDown` проверяет, что ошибок не было.

### CI

`.github/workflows/tests.yml`, задача «Lab 2 · ОС · Python»: Windows и Ubuntu × Python 3.10 и 3.12,
шаги **Unit tests → UI tests → E2E tests**. На Ubuntu поднимается `xvfb-run`: раньше GUI-тесты
там пропускались из-за отсутствия дисплея. `REQUIRE_GUI=1` превращает такой пропуск в ошибку.
`fail-fast: false` — видно результат каждой комбинации. Все 16 проверок на коммите `5aa0ff4` зелёные.

## 5. Найденные и исправленные ошибки

| Ошибка | Причина | Исправление |
|---|---|---|
| `tools/make_sample_data.py` падал с `UnicodeEncodeError` | вывод в канал/файл в Windows идёт в cp1252 | `sys.stdout.reconfigure(errors="replace")`, e2e-тест с `PYTHONIOENCODING=cp1252` |
| UI-тесты в CI на Linux не выполнялись | не было дисплея, тесты пропускались | `xvfb-run` + `REQUIRE_GUI=1` |
| Нестабильный тест `Esc` | зависел от фокуса окна в ОС | хелпер `press()` |
| Низкий контраст бейджей и кнопок | цвета подбирались «на глаз» | палитра выверена по WCAG, проверка в тестах |
| `PhotoImage.transparency_set` в Python 3.10 | метода нет в старых версиях | прямая команда Tk `image transparency set` |
